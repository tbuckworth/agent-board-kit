Setup kit
agent-board-kit
Run a team of Claude Code and Codex agents on an always-on Linux machine, and manage them from your inbox, a Mac menu-bar board and a GitHub to-do list.

This is a self-contained, installable copy of an agent setup that is in daily use. Everything specific to the original owner (names, addresses, accounts, machines, paths) has been taken out and replaced by one config file you fill in. The repository holds the code, an installer with a health check, templates for the agents' instructions, and step-by-step setup guides.

What you get

✉ Email your agents. Every agent mails you from one shared Gmail account. Reply from any device and your reply lands in the exact session that wrote to you, even hours later. Mail no agent owns goes to an orchestrator that starts, relays to and closes agents for you.
⚙ One branch, one worktree, one tmux session per agent. agent-spawn sets it all up (with a memory cap) and launches Claude Code or Codex with a brief; agent-close cleans up, but only once the work is landed.
▦ The agent board. A Mac menu-bar app: every session as a tile coloured by state (busy, waiting on you, blocked, idle, offline), git progress toward main, plan usage, machine load, and right-click actions (message, close, resume, switch model or login).
✓ A to-do list agents can work on. Tasks are issues in a private GitHub repo, edited from a web app or a Mac app. Assign to agent starts an agent on a task; it reports back on the issue and by email.
↻ Free status tracking. Hooks log every turn and agents add one-line milestones; ask "what are the agents up to?" by email for an HTML report.

How it fits together

  1. You email the agents' Gmail address, or reply to an agent's mail.
  2. The mailroom daemon on the Linux machine polls Gmail every 30 s. It only accepts mail from your address with a valid DKIM signature; everything else is held.
  3. A reply goes to the session that sent the original mail (matched by thread, a per-session tag and plus-address). Anything else goes to the orchestrator: one fresh claude -p run with its brief and a small memory file.
  4. Agents work in their own worktrees and tmux sessions, write status notes, open PRs, and mail you when they are done or blocked.
  5. The Mac apps talk to the Linux machine over one SSH connection; nothing listens on a port.

Quick start

First, once: create the agents' Gmail account, a Google Cloud project with the Gmail API and its OAuth client file (docs/02, steps 1–3), and a private to-do repo (gh repo create you/tasks --private). Then, on the Linux machine:

git clone https://github.com/tbuckworth/agent-board-kit ~/code/agent-board-kit cd ~/code/agent-board-kit ./install.sh # creates kit.env nano ~/.config/agent-kit/kit.env # fill in your values ./install.sh # installs (starts nothing) agent-mail-auth # Gmail consent, once ./install.sh --start --labels # start mailroom, make labels loginctl enable-linger $USER # keep services up kit doctor --online # all green?

Then email the agents' address from your own: "Start an agent in my general repo that lists the five largest files and emails me the result." Reply to its mail and the agent gets your reply.

Step by step

Each step has its own guide in the repository's docs/ folder.

1
 Prerequisites. Install git, tmux, python3-venv, the GitHub CLI and Claude Code on the Linux machine; gh auth login; log in to Claude Code. docs/01-prerequisites.md
2
 The agents' Gmail. Create the account; in Google Cloud enable the Gmail API, set up the consent screen (External), add the gmail.modify scope, publish the app (a "Testing" app's tokens expire every 7 days), create a Desktop OAuth client and save its JSON as ~/.config/agent-mail/credentials.json. docs/02-agent-gmail.md
3
 Install. Clone, fill in kit.env, run ./install.sh (idempotent, --dry-run shows every change and backups are kept), give Gmail consent with agent-mail-auth (works over SSH on a headless box), then ./install.sh --start and loginctl enable-linger $USER. docs/03-install.md
4
 Claude Code and Codex. The installer adds status hooks, crossSessionInbound: accept and the agents' global instructions. Optional: a second Claude login with routing by remaining usage and automatic failover. docs/04-claude-and-codex.md
5
 Daily use. Email commands, agent-spawn, tmux and worktree conventions, status reports, closing agents. docs/05-daily-use.md
6
 To-do list. Create a private tasks repo, create its labels (--labels), host the web app anywhere static (it keeps a fine-grained GitHub token in your browser only), optionally build the Mac app. docs/06-todo.md
7
 The Mac. An SSH alias to the Linux machine, then build and install the agent board and to-do apps on the Mac itself (SwiftPM, no Xcode). Mac Claude/Codex sessions can mail through the Linux machine too. docs/07-mac.md
!
 Read the security model first. Agents run without permission prompts, and email can start them. Only your address with a DKIM pass is trusted; use a dedicated machine or user if you can. docs/08-security.md · problems: docs/09-troubleshooting.md

Core and optional parts

Coremailroom and agent commands, orchestrator, global agent instructions and hooks, agent board, to-do list with Assign to agent
Optionalseveral Claude logins with usage routing and failover; per-agent memory caps and RAM warnings; restart-and-resume after OS updates; collaborators' agents as a second, guarded sender tier; Mac sessions mailing through the Linux machine; cloud-watchdog for paid GPU/cloud resources agents launch
Linux onlythe server side uses systemd and /proc. The Mac is a client; running the mailroom on macOS is untested.

Everything personal lives in ~/.config/agent-kit/kit.env; tokens stay in mode-600 files on your machine. Updating is git pull && ./install.sh. kit doctor checks the whole installation and prints the fix for anything that fails.
